# 楼层平面模型（model/）

把 2010 年改扩建方案的 27 张楼层平面图，转成了**结构化 JSON 地图数据** + **网页查看器**。
数据对 AI 友好（改 JSON 即可），对人友好（双击 `viewer.html` 就能看）。

## 看图（给人看）

双击打开项目根目录的 **`viewer.html`**（无需服务器、无需联网）：

- **"校园总图"是列表第一项**：整校手绘地形图，**点蓝色虚线的楼栋直接跳转到对应楼的楼层平面**
  （对应关系已经同学确认：6号楼=体育馆、2号楼=文杰楼、7&8号楼=综合楼、5号楼=公寓、
  3号楼=文心楼、1号楼=行政楼；可在 campus.json 里改 `linkTo` 继续修正）
- 左侧选楼栋 → 楼层条选层 → 主区显示 SVG 平面图（按房间类型配色）
- 滚轮缩放、拖拽平移、`←`/`→` 切楼层
- 悬停显示房间提示；点击房间：详情面板显示名称/编号/面积/可信度/连通房间/楼梯电梯，图上高亮该房间的门洞
- 搜索框：按名称/编号筛选当前楼栋的房间
- 顶栏开关：
  - **原图叠加**：把原始图纸/手绘稿半透明垫在下面，可直观核对转录精度（这是检验/修改数据的主要手段）
  - 名称 / 轴网 / 门口 / 楼梯电梯标注：各类信息的显示开关

## 数据（给 AI / 程序处理）

```
model/
  schema.md        字段格式定义（改数据前先读它）
  buildings/
    综合楼.json     9 层（-2F~7F）227 房间
    公寓楼.json     1F/标准层(2-5F)/6F，102 房间
    文瑞楼.json      3 层，80 房间（实名文瑞楼，图签'规划行政楼'，曾用名行政楼）
    人文艺术楼.json 1~4F，37 房间
    国际部综合楼.json 5 层，77 房间
    文杰楼.json     1F/标准层(2-6F)/7F，67 房间
    体育馆附楼.json  4 层，45 房间
tools/
  validate.py      数据校验：python tools/validate.py
  calibrate.py     比例尺标定：python tools/calibrate.py（改了外轮廓后可重跑）
  build_viewer.py  改完数据后重新生成查看器：python tools/build_viewer.py
viewer.html        生成的查看器（不要手改，改模板 tools/viewer_template.html）
```

每个楼栋 JSON 的核心结构（完整定义见 schema.md）：

- `floors[]` 每层一个，含 `rooms[]`（房间多边形）、`openings[]`（门洞连通）、`vertical[]`（楼梯电梯）、`grid`（轴网）、`outline`（本层有楼板的外轮廓）
- 坐标一律是**原图像素**（图像坐标系，x 右 y 下；多数图为 1164×873，个别层有 `imageSize`），所以改数据时对照原图量就行
- 米制换算：`coordinateSystem.metersPerPixel`，整栋一个系数（估计值，±10~15%）；个别层可带楼层级 `metersPerPixel` 覆盖（`null` 表示未标定，如手绘实测层）
- 校园总图的比例尺 2026-10-29 起为 **0.2413 m/px**（原 `null`），由 2026 卫星配准反推而非图面量取，图纸对现实有约 4% 各向异性，详见 `交接文档.md` §7.9 附；据此算出的面积误差 ±4% 以内
- **综合楼 -2F 有两个版本**：`"-2F"`（2026-10 同学手绘实测版，记忆草图、比例未标定）与
  `"-2F(2010方案)"`（方案图转录存档）。实际建成情况以手绘版为参考基准，详见 `资料/06_实地手绘比对/`

## 改数据的推荐流程（AI 操作）

1. 打开 `viewer.html`，勾选"原图叠加"，找到要改的房间，对照原图确定正确边界
2. 改对应 `model/buildings/<楼名>.json`（坐标直接用原图上量到的像素值）
3. `python tools/validate.py` 校验
4. `python tools/build_viewer.py` 重新生成查看器，刷新页面确认

## 精度说明（重要）

- 来源是 2010-11 的**设计方案**（非竣工图），局部可能与现状不同
- 几何：房间接缝误差约 5~10px（≈0.5~1m），弧形墙用折线近似
- 房间名：原图标注只有 5~8px 高，部分读不清。读不清的写"未识别房间"或推断名，
  `confidence` 字段标注 high/medium/low，`note` 写推断依据。**名字层面的 medium/low 较多**（尤其
  人文艺术楼、文杰楼、体育馆附楼，原图字最小），边界层面大多可信
- 比例尺：由方案《投资估算表》各楼总面积反推。综合楼 0.089、公寓楼 0.092、行政楼 0.092、
  体育馆附楼 0.090（图上有可读尺寸标注，最可靠）、文杰楼 0.092、国际部综合楼 0.086、人文艺术楼 0.085（m/px）。
  五栋独立标定收敛到 0.09 附近，交叉印证了图纸同比例渲染；跨楼比较米数时留 10~15% 余量
- 地下车库面积（估算表 7512㎡）与综合楼地下两层轮廓测算值（约 3580㎡）差约一倍，两种口径
  （地上/地下分列 vs 全楼合计）尚不能完全对齐，比例尺已按"综合楼全楼 12209㎡"口径标定，
  若后续拿到准确尺寸标注可重跑 `calibrate.py`
